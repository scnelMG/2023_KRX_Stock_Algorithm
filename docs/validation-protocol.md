# 검증 프로토콜

## 현재 기록에서 말할 수 있는 것

공개 리더보드에는 팀의 최종 순위와 점수가 남아 있습니다. 반면, 보관된 코드·Notion·Drive 기록에는 최종 모델 선택용 holdout RMSE, 모델 비교표, 재계산 가능한 Sharpe 시계열이 없습니다.

이 저장소는 누락된 수치를 추정하거나 새로 계산한 것처럼 제시하지 않습니다.

## 대회 평가와 구현의 차이

대회는 각 제출 순위의 상위 200개 Long, 하위 200개 Short를 15거래일 동안 거래하는 것으로 가정해 Sharpe 지수를 계산했습니다. `window_slicing.ipynb`는 이 순위를 생성하는 모델링·제출 단계이며, 과거 코드만으로 대회 점수를 재계산하는 검증기는 아닙니다.

## 후속 검증 기준

합법적으로 보유·사용 가능한 시점 고정 데이터가 있을 때만 다음을 수행합니다.

1. 학습 구간, 검증 구간, 최종 제출 구간을 시간순으로 완전히 분리합니다.
2. 각 구간에서 ARIMA와 window 기반 선형 회귀를 같은 종목 universe·feature snapshot으로 실행합니다.
3. 가격 예측은 종목 단위 RMSE와 중앙값 RMSE로, 포트폴리오는 대회와 동일한 Long–Short 규칙의 일별 수익률·15일 Sharpe로 평가합니다.
4. 실행 날짜, 데이터 snapshot 식별자, 라이브러리 버전, 누락 종목과 중립 처리 수를 함께 기록합니다.
5. 검증 결과와 최종 제출을 분리하고, 검증 결과를 보고 모델을 선택한 이유를 표로 남깁니다.

거래비용·세금은 대회 평가에서 고려하지 않았습니다. 실전 성과를 주장하려면 별도의 비용·슬리피지 민감도 분석이 필요합니다.
